# 通话与其他应用兼容性 · 0.1.1

## 目标与边界

地铁助手是普通独立应用。用户必须随时能回桌面、打开电话或使用其他应用。下车提示不能接管屏幕、电话、系统音量或其他应用。

代码限制与模拟器测试可以验证一部分行为，但不能证明所有手机、所有来电和第三方通话场景绝无问题。尤其是实际拨出/接听、蓝牙通话、微信等网络通话及厂商系统，需要在老人手机上实测。

## 已加固

- 无电话、通话记录、联系人、无障碍、系统悬浮窗、设备管理、VPN、全屏 Intent、系统设置写入或修改音频设置权限。不会成为默认拨号器或桌面；不调用拨号/拒接/挂断接口。
- 下车提醒使用本应用窗口内的弹窗和普通通知。返回键或“先关闭提示”可关掉弹窗，不会误确认下车；行程页保留后续确认入口。Home 和切换应用由系统处理。
- 通知不会自动打开 Activity，不抢其他应用的前台窗口，不拉起全屏提示，不主动点亮屏幕、不解除锁屏。
- 到站通知使用新的无声渠道 `alight_v2_quiet`，默认保留视觉和短震动，不绕过勿扰。检测到 AudioManager 的非正常音频模式（例如响铃、通话、网络通话）时，此次通知设为静默（包括抑制震动）。用户自行修改通知渠道时以系统设置为准。
- 语音播报默认关闭。开启后仅在本应用处于前台、系统非通话模式且没有其他媒体播放时尝试短暂音频焦点；不接受延迟获得焦点。获取失败直接放弃，不排队补播。失去焦点、离开应用或检测到通话立即停止；不修改系统音量、扬声器、蓝牙路由或勿扰模式。
- 语音识别也不会在检测到通话/响铃时打开，提示改用文字。没有录音权限，不长期占用麦克风。系统语音服务自身行为仍由系统决定。
- 通知中新增“结束行程”。点击后停止服务、取消备用任务、清空当前行程并取消通知。广播接收器不导出，使用不可变 PendingIntent。
- 到站提醒投递后释放部分唤醒锁，结束持续检查；如有可选播报，最多保留10秒后停止服务。未触发提醒时唤醒锁仍有6小时上限；结束行程立即释放。行程计时会消耗电量，不能承诺零耗电。

## 专项自动检查

最终结果：32项领域测试通过；13项设备测试中12项通过、1项拨号测试因设备缺少拨号应用而跳过，0失败；Lint及Debug构建通过。没有把跳过项计为通过。

测试代码：`app/src/androidTest/java/com/local/eldermetro/CoexistenceTest.kt`。

1. 审计实际安装包合并后的权限，仅允许明确列出的权限；验证无 HOME 入口，服务及结束行程接收器不对外导出。
2. 切到系统设置后触发提醒，系统设置仍为前台，随后可回桌面。
3. 提醒弹窗可用返回键关闭，保持原行程阶段，继续进入设置、回桌面。
4. 从通知结束行程，通知消失、状态归零、当前持有的唤醒锁释放。系统唤醒锁历史仍可能保留使用记录，这不等于仍持有锁。
5. 提醒前后音量、音频模式、铃声模式、勿扰状态不变；通知无全屏 Intent，渠道默认无声且不绕过勿扰。
6. 打开 ACTION_DIAL 拨号界面、输入虚构测试号码并确认提醒不抢前台（**从不点击拨出**）。当前 MuMu Android 15 镜像没有拨号应用，此项明确跳过，不算通过。

## 手机验收必须补做

以下由家属在自己设备上手动完成，不能使用紧急号码作测试：

| 时机 | 操作 | 合格条件 |
| --- | --- | --- |
| 普通首页、计时中、提醒弹窗出现时 | 回桌面打开电话并手动拨打家属号码 | 拨号、通话、挂断都正常，应用不自动跳回 |
| 同上三种时机，包括锁屏 | 另一部手机呼入；分别接听和拒接 | 来电界面、铃声、接听/拒接都由系统正常处理 |
| 已接通电话时 | 等待一次下车提醒 | 通话不断开，不改变通话音量/扬声器，不播报抢声 |
| 开启可选播报时 | 播报过程中来电或切走 | 播报停止，不在通话结束后补播 |
| 使用微信等网络通话或蓝牙耳机 | 等待提醒 | 音频路由、麦克风、通话保持正常 |
| 使用音乐、视频、微信、浏览器 | 等待提醒并继续操作 | 不跳回地铁助手，不暂停或强制改变媒体音量 |
| 锁屏/勿扰/静音/省电模式 | 触发提示并结束行程 | 不解锁屏幕，不绕过勿扰，结束后无持续服务 |

手机品牌、Android版本和系统设置可能影响通知与音频行为。未完成上述真机验收前，交付属于已加固、部分验证的首版，不能宣称已保证实际电话完全不受影响。
